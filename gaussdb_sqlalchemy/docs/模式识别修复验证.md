日期：2026-09-05。

## 模式身份与名称

M 是新的 MySQL 兼容模式，B 是旧的 MySQL 兼容模式。
原实现使用首字母，既拒绝 ORA，又把 MYSQL 误归为 M，同时把 PG 冒称 A。
现改为完整名称映射：A/ORA→A、B/MYSQL→B、M→M、PG→PG。
支持大小写、首尾空白及 DBAPI bytes 返回；未知前缀和未适配的 C/TD 明确拒绝。
PG 保留独立身份，当前复用非 M SQL 实现，不代表已通过 PG 全量验收。

依据：[官方 CREATE DATABASE](https://support.huaweicloud.com/centralized-ref-v10-gaussdb/gaussdb-38-0247.html)
分别列出 MySQL 兼容性 B 模式及 M-Compatibility 模式，并说明 MYSQL-format 对应 B-format。
本地只读核对系统表及 SHOW sql_compatibility：

| 测试库 | 系统表及 SHOW 返回值 | 修正后方言值 |
|---|---|---|
| gdbdrv_a_test | ORA | A |
| gdbdrv_b_test | MYSQL | B |
| gdbdrv_m_test | M | M |

因此上一份[结果转换验证](结果转换与约束反射修复验证.md)中的 MYSQL 库结果，
是在旧代码错误选择 M 方言路径时测得，不能当作识别修正后 B/M 两种模式的全量通过证据。
